# Arena draft + deckbuild automation: design brief

Produced 2026-09-06 by a research workflow (6 angles, 76 load-bearing claims adversarially verified: 66 confirmed, 10 refuted with corrections). Sources are cited inline. Unknowns are listed in section 4 and are the things to measure live before relying on them.

# Design Brief: Fully Automated Arena Draft + Deckbuild on macOS

## 1. Control concept

**One mechanism: Player.log as the state oracle + computed window geometry for input, with a screenshot/OCR verifier only where the log is silent.**

Why this is the smallest set:

- **State is fully log-visible for every draft format.** Pack contents, pick index, running pool, and completion all arrive as `[UnityCrossThreadLogger]` lines (`Draft.Notify`, `EventPlayerDraftMakePick`, `BotDraftDraftStatus/Pick`, `DraftCompleteDraft`, `EventJoin`/`EventGetCoursesV2` `CardPool`). Human P1P1 is now pushed too (17Lands v4.14 removed its P1P1 OCR: https://github.com/unrealities/MTGA_Draft_17Lands/issues/169; 2026-07-07 Contender fixture in https://github.com/unrealities/MTGA_Draft_17Lands/blob/main/tests/test_log_scanner_data.py). Brian's `draft-parser.ts:22` comment and the `LogBusinessEvents/CardsInPack` path are stale and should be deleted.
- **Input must be synthetic HID events (CGEvent) at computed coordinates.** Arena's macOS AX tree is empty (window + 3 buttons + title only; Unity's accessibility plugin is iOS-only: https://developer.apple.com/forums/thread/782704). No deep link, no in-event import, no protocol client that is acceptable (WotC ToS: https://company.wizards.com/en/legal/terms). So clicks are the only write path.
- **Geometry is deterministic from the window rect.** CGWindowListCopyWindowInfo gives the Arena window bounds without any permission (already in `electron/native/arena-window-watch.swift`). Pack cards sit on a fixed grid in fractions of the content box (FirstPick calibration: colX0=0.1469, colPitch=0.1018, row0Y=0.2010, rowPitch=0.2371 — https://github.com/francescolofranco-dev/first-pick `PackGeometry.kt`); deck-list rows have fixed pitch (38 pt at 1800x1169; first row centre y=244 px) and the pool grid is 5 columns at 0.150-width pitch.
- **Order within a screen is derivable from state**: the pack grid order = `PackCards` order (assumption to verify once, see §4); deck-list order = Arena's sort (MV → WUBRG → colourless → alphabetical, multicolour after mono at same MV, lands last); pool grid order = colour → MV → name. Given the pool from the log plus the card DB, every row/cell index is computable, so a target card maps to (x,y) without vision.
- **Log-driven acknowledgement replaces timers.** Every click's effect is observable: a pick → `==> EventPlayerDraftMakePick`/`BotDraftDraftPick` line then next `Draft.Notify`/`DraftStatus`; deck submit → `==> EventSetDeckV3` + `<==` ack (Player-prev.log:1917/1940 for PremierDraft_LTR_20260825; Player.log:1131 for HOB). Wait on the line, not on a sleep (mtga-farm-bot lesson: clicks into animations are silently swallowed — https://github.com/Barrylim366/mtga-farm-bot README).

**Where screenshots/OCR are unavoidable:**

1. **Deckbuild intermediate state.** Arena writes no per-edit event; the decklist reaches the log only on submit. Between clicks the only truth is the screen. Use a one-shot SCScreenshotManager window capture (≈320 ms incl. spawn; no purple indicator) + Vision `.accurate` OCR restricted to the right rail (`regionOfInterest x≥0.70`, ≈220 ms) to read the `N/40 Cards` header and `Nx Name` rows as a *checkpoint verifier* after each batch of clicks, not as the primary locator. Vision reads card names and counts reliably at this font size; confidence is ternary (1.0/0.5/0.3) so don't threshold on it (https://developer.apple.com/forums/thread/695693).
2. **Client-only modals** (disconnect dialog, "Are you sure?", stray Done from card browser) are announced nowhere in the log; detect by OCR/template before clicking.
3. **Hover previews** occlude targets (deck-row hover draws a ~340x500 px card over the pool; pool hover covers the top deck rows). Move the cursor to a neutral spot before capture; FirstPick's `detectShell()` fallback handles the occluded case.
4. **Pick-Two second-pick UI** (Undo button, card removed from grid) — grid reflows after the first pick; treat as a re-derivation from the shrunk `PackCards` if a Notify is emitted mid-turn, otherwise verify by capture (§4).

No hover-feedback channel exists outside GRE duels (`onHover objectId` count: 1121 in a match log, 0 in draft logs), so the hover-sweep trick used by every duel bot is unavailable here.

## 2. Per-format matrix

Method names are currently un-underscored (`EventJoin`, `EventPlayerDraftMakePick`, `DraftCompleteDraft`, `BotDraftDraftStatus`, `BotDraftDraftPick`, `EventGetCoursesV2`, `EventSetDeckV2/V3`); match underscore-insensitively because Arena has flip-flopped (https://github.com/mtgatool/mtgatool-desktop/pull/101; https://github.com/unrealities/MTGA_Draft_17Lands/blob/main/src/utils.py). `<==` responses are a bare `<== Method(guid)` line with JSON on the next line. Event name grammar: `<Family>_<SET|Name>_<YYYYMMDD>`; the same string appears in `EventJoin` request, `Course.InternalEventName`, `DraftCompleteDraft`, bot payloads and `EventSetDeck*`.

Pass direction is memory-only (`PassDirection` in `_currentPickInfo`, https://github.com/mtgatool/mtga-reader/blob/main/src/queries_il2cpp.rs), never logged — not needed for automation.

Format detection: split event name on `_`; recovery mode when `EventJoin` was missed: `Draft.Notify`/`MakePick` ⇒ human, `DraftStatus` ⇒ bot, `CardPool` ⇒ sealed (17Lands `__perform_search_logic`).

## 3. Deckbuilder

**No better path exists than clicking.** No in-event import (import/paste is Decks-tab only — `DeckImportParser` lives under `MainNavigation/DeckBuilder/Utilities`, none under `Draft/`; https://draftsim.com/introducing-sealed-deck-builder/), no URL scheme, no tracker writes decks, and a protocol client (`EventSetDeckV3` via front door) is ToS-prohibited and requires Epic OAuth secrets not extracted. So: **compute the click plan from state, execute, verify by OCR checkpoint, submit, confirm via `EventSetDeckV3`.**

Initial state (deterministic): builder opens with **all** pool cards in main deck + Suggest Lands basics to 17 total lands (e.g. 42 picks incl. 1 nonbasic → 58/40 = 42 + 16 basics); pool grid empty ("No cards could be found with the current filters"). Suggest Lands = `BasicLandSuggester` behind `AutoLandsToggle`, on by default, adds only basics by colour composition to 17 in Limited, and **turns off permanently once you touch lands manually** (https://mtgazone.com/using-arena-interface-and-add-ons/). Whether it re-balances after each spell cut while still enabled is unobserved (§4).

Deterministic edit algorithm:

1. **Model the deck list** as the sorted list of distinct cards: sort key = (MV asc, colour class W<U<B<R<G<multicolour<colourless, name), lands last (basics then nonbasic); duplicates collapse to one `Nx` row. Row i centre = `firstRowY + i·pitch` (38 pt pitch, first row y=244 px at 1800x1169; window-rel fractions must be re-derived per window size — §4). Row x = ~0.90 of width. 16 rows visible above Done; more require wheel scrolling (step unmeasured).
2. **Cut spells first, bottom-up** (removing a row reflows rows above/below; bottom-up keeps unclicked indices stable). Each click on a deck row moves one copy to the pool; for `Nx` rows click N−k times; recompute the model after every click.
3. **Lands.** Two options: (a) leave Suggest Lands on and never touch lands — after spell cuts the basics count should re-target (unverified); (b) set lands explicitly: land filter (icon at x≈746 px in the filter bar, y≈191 px) shows `SUGGEST LANDS`, Plains, Island, Swamp, Mountain, Forest tiles (5-col grid, Forest wraps to row 2); clicking a basic adds one copy (db13→db14: 8x→11x Plains). Nonbasics from the pool do **not** appear in this filter. Clicking a deck-list land row removes one. Touching lands disables auto-suggest, so do it last.
4. **Adding back from pool** (if the plan over-cuts): pool grid is 5 cols × 2 visible rows, sorted colour → MV → name, centres x = 116/308/499/692/883 pt, y = 318/594 pt at 1280x748; index → cell, scroll for row ≥ 3. Single click adds.
5. **Checkpoint**: park cursor off-list, capture window, OCR x≥0.70, parse `(\d+)/40 Cards` and `^(\d+|[Il])\s*[xX×]\s*name$` rows (FirstPick `DeckBuilderScreenInterpreter.kt` regexes and row-synthesis constants). Diff against model; if mismatch, resync model from OCR and continue. Do this after the cut batch and before Done, not per click.
6. **Done** at (0.902, 0.934) of window; then wait for `==> EventSetDeckV3 {EventName,Summary{DeckId,Name:"Draft Deck",Attributes[Format:Draft]},Deck:[{cardId,quantity}]}` + `<== EventSetDeckV3(guid)` — that line is the ground-truth final decklist; verify it equals the plan. Then `EventGetCoursesV2` shows `CurrentModule:"CreateMatch"` + `CourseDeck`.

Avoid: the deck-tile/name pane (opens the details panel and hides rows + Done); the horizontal layout toggle (unmeasured); hovering during capture. Prerequisite: Arena frontmost (Unity ignores input/hover on unfocused windows).

## 4. Impossible or unknown

- **Impossible: accessibility/element-level control.** AX tree is empty (local `axwalk.swift` probe; https://developer.apple.com/forums/thread/782704).
- **Impossible without ToS violation: deck submission or picks by protocol.** `EventSetDeckV2/V3`, `Event_SetJumpStartPacket` exist in the binary and leyline/MTGate decode the front door, but WotC terms forbid it (https://company.wizards.com/en/legal/terms; https://github.com/MTGate/MTGate/blob/master/README.md). Also unknown whether a second session can coexist with the GUI.
- **Impossible: log feedback for hover/cursor position in draft/deckbuild** (0 `onHover` lines in draft logs).
- **Unknown: pack grid order == `PackCards` order.** FirstPick does not assume it (it does Hungarian assignment of log-known cards to detected rects by art signature, `CardRecognizer.kt`), which is weak evidence the screen order may differ or that the author never checked. One live comparison settles it; the current overlay's picks already succeed on this assumption for pick-one.
- **Unknown: Pick-Two intermediate state.** Whether a `Draft.Notify` (or anything) is emitted after the first of two selections; no local PickTwo log. Fixture only shows per-turn Notify with 2-id picks (https://github.com/unrealities/MTGA_Draft_17Lands/blob/main/tests/test_log_scanner_data.py).
- **Unknown: geometry scaling law.** All deckbuilder measurements are from one 1800x1169 scaled-mode capture (1 px = 1 pt) and one 1280x748 window; whether the rail/pool anchor to edges or a centred content box, the wheel step per row, and the horizontal-layout geometry are unmeasured.
- **Unknown: Suggest Lands rebalancing** after spell cuts while still enabled; only MTGAZone's description.
- **Unknown: multicolour vs colourless tie order** at equal MV, and the star icon's effect on sort.
- **Unknown: Unity 6 input on Mac.** Mac client is still Unity 2022.3.62f2 (2026.62.20); Windows 2026.62.30 moved to Unity 6 with WM_POINTER (`EnableMouseInPointer`; https://github.com/dabielf/crossover-unity-mouse-fix). Whether posted CGEvents keep registering after the Mac update must be tested live.
- **Unknown: timer seconds in 2026** for Premier/Trad/Pick-Two/Cube, and which card auto-pick chooses on expiry (patch notes/fandom are Cloudflare-gated).
- **Unknown: Jumpstart/Jump In, Chaos, Arena Direct Draft, Mixed-Up log shapes** — no fixtures anywhere.
- **Unknown: SCK monthly screen-recording re-consent** behaviour on macOS 26 for one-shot captures.
