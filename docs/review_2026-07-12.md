# Adversarial and improvement pass - 2026-07-12

## Outcome

The core DraftFM zero-shot result remains supported by the frozen prediction
artifacts reviewed in this pass. The paper's prior preregistration chronology
was not accurate: `eval-protocol-v1.1` postdated the first automated MSH
download, and a separate serving pipeline trained a per-set MSH model before
the frozen evaluation. The battery weights predated that download and the
serving model shared no parameters with the battery. The paper and protocol
now disclose the exact chronology and quarantine deviation.

This pass also:

- pinned every paper role to an exact run ID and checkpoint sha256;
- made missing or mismatched paper inputs fail instead of selecting a newer run;
- replaced visible pending baseline cells with `not evaluated`;
- renamed the target-trained model from a ceiling to a supervised reference;
- narrowed cross-dataset SOTA and licensed-universe causal language;
- corrected figure provenance and added tracked diagnostic/snapshot metadata;
- fixed tracker play/draw SQL, completed-match replay handling, and late score backfill;
- validated and bounded draft API requests;
- fixed web shell caching, integer count handling, and tablet/mobile layout;
- rebuilt and visually checked both PDFs.

## Residual app risks

- Local-player detection can invert match results when both players report the
  same platform; it needs a stable local identity and parser fixtures.
- Life-total tracking can misclassify ordinary lethal wins as milling because
  missing life values and a real zero currently share one representation.
- Electron distribution still needs explicit x64/arm64 targets, an icon,
  signing, notarization, and release metadata. The current local package is
  arm64-only and unsigned.
- The draft API was not running on port 8100 during this review. Treat that as
  an operational check before testing the live draft overlay.
